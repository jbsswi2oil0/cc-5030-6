# 注释锚点原型：媒体时间区间 vs 帧内容签名

本原型在既有逐帧审阅入口上接入两种注释锚点定位器，并用重编码、剪切、重复镜头三类派生素材量化取舍。结论不是“签名可靠”，而是：**时间锚点在时间轴不变时精确、时间轴一变就拒绝自证；签名锚点能跨重编码找回同一画面，但无法唯一识别重复镜头，歧义以候选数量呈现。**

## 1. 两种锚点

定义见 `server/anchors.js`，两者同时写入每条注释（`store.addAnnotation`），并附 `anchorCheck`：写入时用当前素材自检一次，避免存储的锚点看起来“默认有效”。

| | 媒体时间区间锚点 | 帧内容签名锚点 |
|---|---|---|
| 依据 | 绝对 PTS、帧内区间、`timeBase`、`firstPtsTime`、`frameCount` | 16×16 平均亮度网格（256 字节） |
| 定位 | 先找精确 PTS；找不到退回区间重叠；再无则按相对时间取最近帧 | 阈值内全部候选，按距离排序 |
| 何时可信 | 仅在时间轴指纹（帧数/时基/起始 PTS）完全一致时 `reliable: true` | 只有一个候选时 `resolved`；多个即 `ambiguous`；零个即 `not-found` |
| 明确拒绝 | 剪切/重定时后 PTS 变了也照实标 `reliable: false` | 不提供“取最近帧”兜底；阈值必须随锚点存储 |

`locateByContent` 遇到缺失阈值、算法不匹配会直接抛错（`server/anchors.js:181`），不存在默认阈值遮错。

## 2. 实验材料与复算方式

实验脚本：`tools/experiment-anchors.js`（`npm run experiment` 会刷新 `data/experiments/anchor-results.json`）。
测试：`test/experiment.js`（`npm run test:experiment`）会用提交的素材重新生成派生素材、重算全部数字，并断言文档引用的结论；**数据不是手填的**。

源素材：`data/samples/cfr-frame-numbers.mp4`，60 帧，CFR 30fps，time_base 1/15360。派生副本：

- **重编码**：`scale=256:192` + libx264 CRF 30
- **剪切**：保留源帧 15–44（30 帧），时间轴重新从 0 开始
- **重复镜头**：整段拼接两遍（120 帧，每个画面出现两次）

探测帧：0, 1, 7, 15, 22, 30, 31, 44, 59。

## 3. 结果（`data/experiments/anchor-results.json` 可复算）

### 3.1 签名漂移（同帧、不同副本的签名距离）

| 副本 | 最小 | 中位 | 最大 |
|---|---|---|---|
| 重编码 | 0.839 | 1.019 | 1.484 |
| 剪切 | 0.313 | 0.364 | 0.433 |
| 重复 | 0.306 | 0.395 | 0.538 |

源素材内任意两帧的最小距离约 3.2；阈值取 2.5，重编码漂移最大值 1.484 仍低于该阈值，但与源内最小距离之间留有间隔。

### 3.2 定位误差（单位：帧）

| 副本 | 时间锚点可靠命中 | 时间锚点最大误差 | 签名锚点唯一命中 | 签名锚点最大误差 | 签名歧义候选数 |
|---|---|---|---|---|---|
| 重编码 | 9 / 9 | 0 | 9 / 9 | 0 | 1 |
| 剪切 | 0 / 5（全部标不可靠） | — | 5 / 5 | 0 | 1 |
| 重复 | 0 / 9（全部标不可靠） | — | 0 / 9 | — | **每条 2 个** |

补充事实（写入 `absentProbes`）：在剪切副本里探测源帧 0、1、7、59（这些帧已被剪掉），签名锚点均返回 `not-found`（0 候选）——这是有利的保守性，但并不能证明签名能区分“相似但不同的画面”；见第 5 节。

## 4. 取舍

- **时间锚点**：时间轴不变时零误差、零歧义，是最便宜可靠的默认。代价是它对任何重编码/重定时都“全有或全无”：剪切后它会明说不可靠，而不是假装命中。
- **签名锚点**：能跨重编码找回同一画面（9/9，误差 0），但重复镜头下必然歧义（每条 2 个候选）。因此界面从不把首个候选当答案，而是显示候选数量。
- **两者的组合结论**：定位器不自动合并成一个“最终帧”。时间锚点给出可不可信，签名锚点给出有几个候选；当二者冲突时，原型把两个结果并列交给人，而不是让代码择一。

## 5. 明确不声称的结论（假设 / 待验）

以下均为**未验证假设**，不应被本原型的通过结果当作已证：

1. **签名不能唯一识别重复画面**——这是本原型的结论，不是待验项。重复副本上每条注释都出现 2 个候选，已由 `test/experiment.js` 断言。
2. **不同内容但视觉相似的镜头会碰撞**——未验证。现有素材里相邻帧差异明显；真实影视素材中的黑场、渐隐、纯色字幕卡可能让不同时间点的签名距离低于阈值。需用真实素材扩充实验后才能下结论。
3. **阈值 2.5 可迁移到其它编码/分辨率**——未验证。当前阈值只在这三份派生素材上测过；更高压缩比、更低分辨率或不同编码器可能把漂移推过阈值。不要把 2.5 当成通用常数。
4. **签名对裁切/旋转/色彩变换的稳定性**——未验证。实验只覆盖缩放到 256×192 与重新编码，没有覆盖画面裁切、旋转、调色或帧率转换。
5. **VFR 素材上的时间锚点**——现有实验副本均为 CFR。VFR 下绝对 PTS 仍精确，但剪切后 VFR 的时间轴重建更复杂，需单独实验。

## 6. 已知限制

- 签名在入库时一次性计算并随媒体存储；同一内容重新上传（相同字节）会复用同一签名表，不重新计算。
- 旧记录（本原型之前入库）缺失签名表；首次访问时从已存文件补算，若文件缺失则显式报错，不会用默认值顶替（`server/store.js` 的 `ensureSignatureTable`）。
- 注释编辑（`PATCH`）只改文字/轨道，帧与两种锚点不可变，避免“编辑者改变原始位置”。

## 7. 运行

```bash
cd frame-review
npm install                      # 已装则可跳过
npm run gen-media                # 可选：重新生成 data/samples 三份素材
npm start                        # http://localhost:8080
```

界面使用：打开页面 → 选择/上传素材 → 用“上一帧/下一帧/跳帧”点选帧 → 在画面上拖拽框选并写文字，注释会同时带两种锚点落库 → 在右侧点选一条注释，下方“注释锚点定位”面板显示两种锚点的写入自检；把“对照目标素材”切到重编码/剪切/重复副本，点“用两种锚点重新定位”，面板会并列显示时间锚点可靠性与签名候选数量，并实际跳到时间锚点结果帧。

实验与测试：

```bash
npm run experiment        # 刷新 data/experiments/anchor-results.json
npm run test:unit         # 23 项单元断言（含两种定位器与“阈值缺失即报错”）
npm run test:experiment   # 7 项实验断言，重算并核对文档数字
npm test                  # Playwright 端到端（20 项：旧 12 + 锚点 8）
```

本环境中 Playwright 需要 Chromium 的系统库；若浏览器报缺 `libnspr4` 等，请设置 `LD_LIBRARY_PATH` 指向已解包的库目录，或安装系统依赖后重试。

## 8. 接入点

- `server/anchors.js`：两种锚点的构建、定位与校验（纯函数，无 I/O，单测直接覆盖）。
- `server/signature.js`：签名提取与距离；阈值与网格尺寸在此定义，实验脚本引用同一常量。
- `server/store.js`：入库时建签名表；写注释时生成锚点与 `anchorCheck`。
- `server/index.js`：`GET /api/media/:cid/annotations/:aid?target=:tid` 返回两种定位器结果。
- `public/app.js`：锚点对照面板、注释选择/编辑；面板结果驱动 `FrameEngine.seekToFrame`，失败经 `flash` 回到逐帧审阅界面。
